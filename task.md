# Веб-интерфейс для моделирования матчей и турниров

Библиотека `tourn.py` уже поправлена и проверена. Этот план только про приложение. Ноутбуки продолжают звать библиотеку по-старому.

## Цель
Локальное приложение на Streamlit, в котором можно проиграть один матч, много матчей, один турнир и много турниров на актуальных рейтингах Opta.

## Стек и устройство
- Python, Streamlit, Plotly, PyYAML.
- Postgres нет. Деплой не делаем, только локальный запуск.
- `ab_game` — образец раскладки (конфиг, отдельный модуль расчёта, отдельный модуль графиков, тонкий Streamlit), без её логирования и проверок.
- Интерфейс на русском.
- Запуск: `streamlit run ui/streamlit_app.py`

```
settings.yaml
requirements.txt
tourn.py                      # готовая библиотека
opta-power-rankings.csv       # 14403 клуба, opta_rating и start_rating
core/config.py                # чтение settings.yaml
core/teams.py                 # каталог, пресеты, правка рейтинга
core/factors.py               # хозяева, погода, состав, усталость
core/simulate.py              # матч и турнир для веба, с колбэком прогресса
ui/streamlit_app.py
ui/charts.py
tests/test_factors.py
```

Факторы матча в `tourn.py` не переносятся. Расписания, жеребьёвка, таблица и `get_match` берутся из библиотеки. Цикл турнира для веба живёт в `core/simulate.py` и сам подставляет рейтинг и сигму каждого матча. Если для швейцарки или плей-офф без копии кода не обойтись, в библиотеку добавляется необязательный аргумент со старым значением по умолчанию, чтобы ноутбуки не изменились.

## Данные
Файл `opta-power-rankings.csv`. В модель идёт `start_rating = opta_rating × 24`. Колонка `opta_rating` показывается рядом, чтобы было видно исходный балл 0–100.

Пресеты, все из этого файла:

- Топ-8 мира
- Топ-32 мира
- Английская Премьер-лига, Ла Лига, Бундеслига, Серия A, Лига 1

Свой набор — поиск по названию в полном списке. У выбранной команды рейтинг подставляется сразу, его можно заменить вручную. Список лиги чемпионов в файле нет, его можно собрать поиском.

Швейцарка требует чётное число команд. При нечётном приложение не стартует и пишет, почему.

## Модель матча в интерфейсе
База из библиотеки: разница мячей — округлённая нормальная величина со средним `mu` и разбросом `sigma`. Потолок `mu` около 3.3 мяча остаётся.

Из конфига:

- базовая `sigma` = 2.5
- база голов проигравшего — целое от 0 до 1 включительно, как исправленный вызов `total=(0, 1)`
- бонус хозяев: **+0.4 к `mu`**. По умолчанию хозяина нет, играют на нейтральном поле. Хозяином можно назначить одну из двух команд. Число общее для всех и лежит в конфиге.

Погода умножает сигму:

| Состояние | Множитель сигмы |
|---|---|
| ясно | +0% |
| слабый ветер | +0% |
| сильный ветер | +5% |
| слабый дождь | +5% |
| сильный дождь | +15% |

На вкладках одного матча состояние выбирает пользователь. В турнире, если фактор включён, погода независима в каждом матче. Вероятности в конфиге, стартовые значения: ясно 70%, слабый ветер 10%, сильный ветер 8%, слабый дождь 8%, сильный дождь 4%. Слабый ветер не меняет сигму, но в протоколе матча пишется отдельно.

Состав, 0–100%, по умолчанию 100%. Сдвиг рейтинга:

`(состав − 100) / 50 × 241`

Пятьдесят процентов состава дают минус 2 мяча ожидаемой разницы против равного соперника. У явного фаворита тот же сдвиг уменьшает `mu` меньше чем на 2, потому что `mu` выходит на потолок.

Усталость только в турнире и только если фактор включён. Среднее состава после `g` уже сыгранных в этом турнире матчей:

`0.50 + 0.50 × exp(−g / 150)`

Старт 100%, после 15 матчей около 95%, пол 50%. На матч берётся нормальное значение вокруг этого среднего с разбросом 5 процентных пунктов и обрезается в 0–100%. На вкладках одного матча усталости нет, там состав задают бегунки.

Пенальти после ничьей в плей-офф — честная монета, без рейтинга и состава. В круговой таблице очки 3/1/0.

## Вкладки

### 1. Один матч
Две команды из списка, рейтинги, правка рейтинга, хозяин, погода, два бегунка состава. Кнопка «Симулировать матч».

На экране: счёт, `mu`, `sigma` и три вероятности исхода. Вероятности считаются по нормальному распределению разницы мячей до округления: победа при разнице от +0.5, ничья от −0.5 до +0.5, поражение ниже −0.5. База голов на эти вероятности не влияет.

### 2. Много матчей
Те же настройки и число симуляций, по умолчанию 1000.

График вероятностей разницы мячей (`+1`, `−3`, …). Отдельно вероятность победы каждой команды и ничьей. Прогресс-бар: сделано N из M и процент.

### 3. Один турнир
Пресет или свой список. Формат:

- на вылет, посев по рейтингу или случайный
- круг, число кругов задаёт пользователь
- группа и плей-офф: число групп, сколько выходит, число кругов в группе, посев плей-офф
- швейцарка, число туров

Переключатели погоды и усталости.

Если матчей больше 10, список лежит в свёрнутом блоке. В таблице всегда есть название, забитые, пропущенные и разница. Для круга, швейцарки и группы ещё игры, очки, победы, ничьи, поражения и место. Для плей-офф — место, раунд вылета и путь по сетке.

### 4. Много турниров
Те же настройки и число симуляций, по умолчанию 1000. Прогресс-бар, как на второй вкладке.

Тепловая карта «команда × место», команды сверху вниз по рейтингу. Под картой — индекс справедливости той же формулой, что в `get_multiverse_stat`, и вероятность, что команда с самым высоким рейтингом займёт первое место.

Тысяча двукруговых турниров на 32 команды занимает около минуты. Полоса обновляется по ходу цикла, без тысячи перерисовок страницы.

## Порядок работы
1. Каркас: `settings.yaml`, зависимости, пустые четыре вкладки, каталог команд и пресеты.
2. Факторы матча и тесты на бонус хозяев, множители погоды, сдвиг состава и кривую усталости.
3. Вкладка одного матча.
4. Вкладка многих матчей и график разницы мячей.
5. Один турнир: четыре формата, протокол, таблица.
6. Много турниров: прогресс, тепловая карта, индекс справедливости, шанс фаворита.
7. Прогон основных сценариев локально: один матч, 200 повторов матча, короткий круг и короткий плей-офф.

## Не входит в эту итерацию
Деплой, Postgres, правка формулы `mu`, смена множителя 24 у рейтингов Opta.
